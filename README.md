# Champions Lab

ポケモンチャンピオンズの使用率（環境）から、構築を考えるための Web アプリ。

https://123yoshidandy.github.io/pokemon-champions/

## できること

ダブルとシングルを、画面の上で切り替えられる。

### 環境
- 使用率の順位（前日からの上下、タイプ、よく使われる持ち物、メガシンカの有無）
- 名前（ひらがな・カタカナ・英語）とタイプでの絞り込み
- 上位の傾向（多いタイプ、よく使われる攻撃技のタイプ、攻撃のタイプごとに弱点・半減以下になる数、すばやさライン）。上位10・30・50・100体から選べる

### ポケモンの詳細
- 技・持ち物（1%以下は出さない）・特性・性格・能力ポイントの採用率、一緒に使われるポケモン。能力ポイントは、4ポイント以上振った能力の組み合わせ（HA・CS など）でまとめる
- 実数値とすばやさの目安（最速・準速・無振り・最遅）、受けるタイプ相性、メガシンカ後のすがた
- 順位の推移、ポケモン徹底攻略の図鑑へのリンク
- 環境の上位との対面（有利・不利）。上位10・30・50・100体から選べる（環境の傾向と共通）

### おすすめの構築（提案）
- 環境の上位から、6体の構築を5つ提案する（似すぎないように、顔ぶれを変える）
- 点の付け方：上位の相手それぞれに有利なメンバーがいるか（順位で重み付け）、弱点が重なるタイプ、よく組まれる組み合わせ
- 軸のポケモン（2体まで）や、いまの構築を軸にして空いた枠を埋めることもできる
- スタイル（はれ・あめ・すなあらし・ゆき・トリックルーム・おいかぜ）を指定すると、始動役を必ず入れ、その場を活かせるポケモンを優先する
- 持ち物は重ならないように、メガシンカは1体までにする。「この構築を使う」で構築の画面に入れられる

### 構築
- 6体の編集（入れたポケモンは、よく使われる型で埋まる。持ち物は重ならないように選ぶ）
- 持ち物の重なり・メガシンカ2体・能力ポイントの上限超えの注意
- 環境チェック：上位20〜80体それぞれに、メンバーの誰が有利かの表と、勝てるメンバーがいない相手
- 相方の提案：上位の相手への勝ち筋が増える・弱点を受けられる・よく組まれる順
- タイプ相性表（受け）と、攻撃技の範囲
- すばやさの並び（環境の上位40体と比べる）
- 共有のリンク、名前を付けて保存、Showdown 形式の書き出し・取り込み、日本語のメモ

### 選出
- 相手の6体に対して、選ぶメンバー（ダブル4体・シングル3体）と先発の提案、対面表、相手のよく使われる型

### ダメージ計算
- 自分の構築や環境のポケモンを選んで、技ごとの確定数・乱数を計算する（天気・フィールド・急所・壁・てだすけ・ランク補正など）

## データ

- 使用率・採用データ・種族: [Pokemon Champions Battle Data](https://championsbattledata.com/)（ゲーム内のバトルデータを集めているファンサイト）
- 日本語名: [PokeAPI](https://github.com/PokeAPI/pokeapi) の CSV
- 技の性能: [Pokémon Showdown](https://play.pokemonshowdown.com/data/moves.json)
- ポケモンの絵: Pokémon Showdown の画像（画面から直接読み込む。チャンピオンズで新しく出たメガシンカなど、絵がないものは元のすがたの絵）

GitHub Actions（`.github/workflows/update-data.yml`）が毎日 19:30（日本時間）にデータを取り直し、テストが通れば `data/` をコミットする。順位の推移（`data/history/`）は、このときに記録していく。

取得元は個人のファンサイトなので、負荷をかけないようにしている。

- 取得元のデータの版が前回と同じなら、何も取らずに終える
- 同時に2本まで、1件ごとに 0.4 秒空ける（全部で約800件、5〜6分）
- やり直すのは、つながらないとき・429・5xx だけ（429 は Retry-After に従う）。10件続けて失敗したら打ち切る
- PokeAPI と Showdown のデータは `scripts/cache/reference.json` に保存して使い回す（30日ごとか、知らない技が出たときに取り直す）

取得元から止めてほしいと言われたら、すぐに自動の取得を止める。

```bash
gh workflow disable update-data.yml   # 再開は gh workflow enable update-data.yml
```

日本語名がないもの（チャンピオンズで新しく出た特性など）は英語で表示される。`data/names-ja-overrides.json` に書くと、その名前で上書きできる。

```json
{ "abilities": { "Fire Mane": "（日本語名）" } }
```

## 計算の前提

- 実数値は Lv50・個体値31。能力ポイント（合計66・1つ最大32）は、1ポイントで実数値が1上がるとして計算する
- 対面の有利・不利は、お互いのよく使われる型（技・持ち物・特性・性格・能力ポイント）で、一番通る技を交互に打ち合い、最後に立っている方を有利とする。勝った方の残りHPが多いほど、有利の度合いを大きくする（◎ は HP が7割ほど残る勝ち）
  - 動く順は、すばやさ（こだわりスカーフは1.5倍）。遅くても、先制技で倒しきれるときは先制技を使う
  - マルチスケイル・ファントムガードは、HP が満タンのときだけ効く。いのちのたま・反動技・ゴツゴツメット・さめはだの反動で HP が減ると、自分のマルチスケイルも切れる
  - いかくは、場に出たときに相手のこうげきを1段階下げる（まけんき・かちきは上がる）
- ダメージ計算は第9世代の式をもとにした簡易版。2〜5回当たる技は3回で計算する。きあいのタスキ・交代・補助技・おいかぜなどは考えない
- Showdown 形式では、能力ポイントを努力値（ポイント×8、上限252）として書き出す

## 開発

```bash
npm install
npm test                    # テスト（Vitest）
python3 -m http.server      # http://localhost:8000/ で開く
node scripts/fetch-data.mjs # データを取り直す（--force で版が同じでも取り直す）
```

素の HTML / CSS / JavaScript（ES Modules）で、ビルドはない。
