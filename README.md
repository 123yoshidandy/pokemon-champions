# Champions Lab

ポケモンチャンピオンズの使用率（環境）から、構築を考えるための Web アプリ。

https://123yoshidandy.github.io/pokemon-champions/

## できること

ダブルとシングルを、画面の上で切り替えられる。

上の「メガ」で、メガシンカバトル（メガシンカできるポケモンだけが使えるルール。メガシンカは1試合に1体）に切り替えられる。このルールの使用率はないので、ふつうの使用率を、メガシンカのすがたがある種族（チャンピオンズで新しく出たメガも含む。地方のすがたなど、そのすがたにメガシンカがないものは除く）だけに絞って使う。順位・前回の順位・順位の推移・一緒に使われるポケモンは、絞ったあとで付け直す。環境・詳細・構築・提案・選出・計算のすべてが、絞った環境で動く。構築・保存した構築・選出の相手は、ふつうのルールとは別に保存する

### 環境
- 使用率の順位（前日からの上下、タイプ、よく使われる持ち物、メガシンカの有無）
- 名前（ひらがな・カタカナ・英語）とタイプでの絞り込み
- 上位の傾向（多いタイプ、よく使われる攻撃技のタイプ、攻撃のタイプごとに弱点・半減以下になる数、すばやさライン）。上位10・30・50・100体から選べる

### ポケモンの詳細
- 技・持ち物（1%以下は出さない）・特性・性格・能力ポイントの採用率、一緒に使われるポケモン。能力ポイントは、4ポイント以上振った能力の組み合わせ（HA・CS など）でまとめる
- 実数値とすばやさの目安（最速・準速・無振り・最遅）、受けるタイプ相性、メガシンカ後のすがた
- 順位の推移、ポケモン徹底攻略の図鑑へのリンク
- 環境の上位との対面（有利・不利）。上位10・30・50・100体から選べる（環境の傾向と共通）

### おすすめの構築（提案）
- 環境の上位から、6体の構築を5つ提案する（似すぎないように、顔ぶれを変える）
- 一番の構築：ありそうな相手の構築（使用率と「一緒に使われるポケモン」から作った80個）と、選出からターンを追って戦わせ、使用率で重みを付けた勝率が一番高い構築を出す。重いので GitHub Actions で毎日計算しておく（下の「一番の構築の計算」）。計算がまだないデータでは、上位100体から上位60体に一番勝てる構築を、この場で簡単に選ぶ
- マイナー軸：上位50体の外（150位まで）から、上位の相手に勝てる数が多く、特に上位のポケモンがあまり勝てない相手に勝てるものを5体選び、1体ずつ軸にして構築を出す
- 点の付け方：上位の相手それぞれに有利なメンバーがいるか（順位で重み付け）、弱点が重なるタイプ、よく組まれる組み合わせ
- ダブルでは、構築の誰かが使える支援（おいかぜ・トリックルーム・リフレクター・ひかりのかべ・オーロラベール・いかく・ねこだまし・このゆびとまれ・いかりのこな）を、全員の対面に入れて比べる。おいかぜとトリックルームは、相手ごとに有利な方を使う。構築の環境チェックと相方の提案も同じ
- 軸のポケモン（2体まで）や、いまの構築を軸にして空いた枠を埋めることもできる
- スタイル（はれ・あめ・すなあらし・ゆき・トリックルーム・おいかぜ・滅び・バトン・介護）を指定すると、始動役を必ず入れ、その場を活かせるポケモンを優先する
  - 滅び：ほろびのうたと、まもる・ねこだましなどで時間を稼げるポケモン。バトン：バトンタッチと、能力を上げる技を使うポケモン。介護（ダブルだけ）：このゆびとまれ・いかりのこな・サイドチェンジと、能力を上げる技を使うエース
  - 始動の技が、よく使われる4つの技に入っていなくても、採用率5%以上なら入れた型で比べる。候補の範囲の外の始動役も足す
- 違う天気を起こす特性（ひでり・あめふらし・すなおこし・ゆきふらし。メガシンカ後の特性も含む）どうしや、違うフィールドを張る特性どうしは、同じ構築に入れない。天気に頼る技・特性（ウェザーボール・ソーラービーム・オーロラベール・すいすい・ようりょくそ など）が構築の天気と合わないメンバーは減点し、理由に出す。相方の提案も同じ
- 持ち物は重ならないように、メガシンカは1体までにする。「この構築を使う」で構築の画面に入れられる。保存のボタンで、名前を付けて保存できる（構築の画面の「保存した構築」から読み込む）

### 構築
- 6体の編集（入れたポケモンは、よく使われる型で埋まる。持ち物は重ならないように選ぶ）
- 耐久調整：上位30体のよく使われる技のうち、1発で倒されうる技ごとに、確定で耐える一番少ない HP・ぼうぎょ・とくぼうの配分（こうげき・とくこう・すばやさと性格はそのまま。足りなければ、あと何ポイント要るか）
- 持ち物の重なり・メガシンカ2体・能力ポイントの上限超えの注意
- 環境チェック：上位20〜80体それぞれに、メンバーの誰が有利かの表と、勝てるメンバーがいない相手
- 相方の提案：上位の相手への勝ち筋が増える・弱点を受けられる・よく組まれる順
- タイプ相性表（受け）と、攻撃技の範囲
- すばやさの並び（環境の上位40体と比べる）
- 戦い方：環境の上位30体に一番勝ち筋が多い選び方（ダブル4体・シングル3体）を基本選出とし、おいかぜ・トリックルーム・ねこだましなど場を作る役を先発にして、先発と後発の役目を文で出す（おすすめの構築にも、基本選出を1行で出す）
- 共有のリンク、名前を付けて保存、Showdown 形式の書き出し・取り込み、日本語のメモ

### 選出
- 相手の6体に対して、選ぶメンバー（ダブル4体・シングル3体）と先発の提案、対面表、相手のよく使われる型

### ダメージ計算
- 自分の構築や環境のポケモンを選んで、技ごとの確定数・乱数を計算する（天気・フィールド・急所・壁・てだすけ・ランク補正など）

## データ

- 使用率・採用データ・種族: ゲーム内のバトルデータを集めている個人のファンサイト（出典は画面に表示している）
- 日本語名: [PokeAPI](https://github.com/PokeAPI/pokeapi) の CSV
- 技の性能: [Pokémon Showdown](https://play.pokemonshowdown.com/data/moves.json)
- ポケモンの絵: Pokémon Showdown の画像（画面から直接読み込む。チャンピオンズで新しく出たメガシンカなど、絵がないものは元のすがたの絵）

GitHub Actions（`.github/workflows/update-data.yml`）が毎日 19:30（日本時間）にデータを取り直し、テストが通れば `data/` をコミットする。順位の推移（`data/history/`）は、このときに記録していく。

取得元は個人のファンサイトなので、負荷をかけないようにしている。

- 取得元のデータの版が前回と同じなら、何も取らずに終える
- 同時に2本まで、1件ごとに 0.4 秒空ける（全部で約800件、5〜6分）
- やり直すのは、つながらないとき・429・5xx だけ（429 は Retry-After に従う）。10件続けて失敗したら打ち切る
- PokeAPI と Showdown のデータは `scripts/cache/reference.json` に保存して使い回す（30日ごとか、知らない技が出たときに取り直す）

取得元から止めてほしいと言われたら、すぐに自動の取得を止める。

```bash
gh workflow disable update-data.yml   # 再開は gh workflow enable update-data.yml
```

日本語名がないもの（チャンピオンズで新しく出た特性など）は英語で表示される。`data/names-ja-overrides.json` に書くと、その名前で上書きできる。

```json
{ "abilities": { "Fire Mane": "（日本語名）" } }
```

## 計算の前提

- 実数値は Lv50・個体値31。能力ポイント（合計66・1つ最大32）は、1ポイントで実数値が1上がるとして計算する
- 対面の有利・不利は、お互いのよく使われる型（技・持ち物・特性・性格・能力ポイント）で、一番通る技を交互に打ち合い、最後に立っている方を有利とする。勝った方の残りHPが多いほど、有利の度合いを大きくする（◎ は HP が7割ほど残る勝ち）
  - 動く順は、すばやさ（こだわりスカーフは1.5倍）。遅くても、先制技で倒しきれるときは先制技を使う
  - マルチスケイル・ファントムガードは、HP が満タンのときだけ効く。いのちのたま・反動技・ゴツゴツメット・さめはだの反動で HP が減ると、自分のマルチスケイルも切れる
  - いかくは、場に出たときに相手のこうげきを1段階下げる（まけんき・かちきは上がる）
  - こだわりアイテムでは、最初に選んだ技のまま（先制技に切り替えない）。ソーラービームなどのため技は、はれ（ソーラー技）かパワフルハーブでなければ2ターンに1回とする
  - 片方だけが天気を変える特性（ひでり・あめふらし・すなおこし・ゆきふらし）なら、その天気で戦う
- よく使われる型は、持ち物に技・性格・能力ポイントを合わせる。こだわりアイテム・とつげきチョッキでは変化技とねこだましを外して攻撃技4つにし（そろわなければその持ち物を選ばない）、性格と配分は攻撃技の物理・特殊に合わせる。きあいのタスキはHPに振らない配分にする
- メガストーンの採用率が50%以上の種族は、使用率データがほとんどメガシンカの型なので、ふつうのルールの提案・相方の提案では、メガなしの型を候補にしない（メガシンカバトルでは、持ち物に合わせて組み直した型を使う）
- ダメージ計算は第9世代の式をもとにした簡易版。2〜5回当たる技は3回で計算する。きあいのタスキ・交代・補助技・おいかぜなどは考えない
- Showdown 形式では、能力ポイントを努力値（ポイント×8、上限252）として書き出す

## 一番の構築の計算

`scripts/best-teams.mjs` が、4つのルール（ダブル・シングル・それぞれのメガシンカバトル）ごとに計算して `data/best-teams.json` に書く。データの更新のワークフローで、毎日データを取り直したあとに動く（手元のデータだけを使い、取得はしない）。4つのルールを同時に別のジョブで計算し、結果を artifact で受け渡して、最後のジョブでまとめてコミットする。1つのルールの計算が失敗しても、そのルールは前の結果を残す（画面は、ルールごとにデータの版が同じかを見て、古ければこの場の計算に戻る）。

- 相手：上位80体から、使用率の高いポケモンを軸に、「一緒に使われるポケモン」の上位ほど選ばれやすくして6体を足した構築を80個（型はよく使われる型）。重みはメンバーの使用率の重みの平均
- 対戦（`js/sim.js`）：お互いに相手の6体を見て選出（ダブル4体・シングル3体）し、ターンを追って戦う。乱数・急所・命中はシード付きで、同じデータなら同じ結果になる
  - 扱うもの：すばやさ（スカーフ・おいかぜ・トリックルーム・すいすいなど・ランク）、優先度（先制技・いたずらごころ・グラススライダー）、こだわりの技の固定、いのちのたま・反動技・ゴツゴツメット、きあいのタスキ・がんじょう、オボンのみ、半減の実、たべのこし、いかく・まけんき、マルチスケイル、天気とフィールドの特性（ターン数つき）、すなあらしのダメージ、まもる（続けると成功しにくい）、ねこだまし、このゆびとまれ・いかりのこな、壁、ため技、能力を下げる追加効果と自分の能力が下がる技、おはかまいり・そうだいしょう、ダブルの全体技（味方に当たる技は味方への打点を差し引く）、倒れたときと打点がないときの交代
  - 扱わないもの：状態異常（やけど・まひ・ねむり）と、それを起こす技、能力を上げる技（積み技）、てだすけ・アンコール・ちょうはつなどの変化技、ひるみ・こんらんなどの確率の追加効果、とんぼがえり・すてゼリフなどの交代技、相手の行動を読んだ交代、ステルスロック
- 探し方：今の提案の結果（5つ）から始め、メンバー・持ち物・メガシンカする1体を1つずつ入れ替えて、相手80個と8回ずつ戦わせた勝率が上がれば受け入れる（500回）。最後に、上位5つと初期値を、探索に使っていない別の相手の構築群80個と40回ずつ戦わせて選び直す。画面に出す勝率は、さらに別の相手の構築群80個で測った値（探索した相手に合わせすぎていないかを見るため）。天気とフィールドのぶつかり・メガは1体まで・持ち物の重なりなし、などの規則は守る

```bash
node scripts/best-teams.mjs                # データの版が前回と同じなら何もしない（--force で計算し直す）
node scripts/best-teams.mjs --quick --only singles   # 短い設定で1つのルールだけ通す（ファイルには書かない）
node scripts/best-teams.mjs --rule doubles --out best-doubles.json   # 1つのルールだけ計算する（同時に動かすとき）
node scripts/best-teams.mjs --merge best-*.json      # ルールごとの結果を data/best-teams.json にまとめる
```

## 開発

```bash
npm install
npm test                    # テスト（Vitest）
python3 -m http.server      # http://localhost:8000/ で開く
node scripts/fetch-data.mjs # データを取り直す（--force で版が同じでも取り直す）
```

素の HTML / CSS / JavaScript（ES Modules）で、ビルドはない。
